🚀 1. Framework de dashboard de télémétrie (TRÈS bon choix)
💡 Idée

Un framework web (HTML/CSS/JS) pour afficher les données d’un CANSAT :

altitude

température

pression

accélération

vitesse

état du système

🛠️ Ce que tu développes

Un mini-framework qui fournit :

composants prêts à l’emploi :

cartes de données

jauges

graphiques

indicateurs d’état (OK / WARNING / ERROR)

thème sombre / clair

responsive (PC / tablette)

📦 Exemple d’utilisation
<telemetry-card label="Altitude" unit="m" value="325"/>
<telemetry-gauge label="Température" value="22"/>

⭐ Pourquoi c’est excellent

✅ Directement lié au CANSAT
✅ Très visuel
✅ Facile à expliquer à un jury
✅ Peut être utilisé en vrai pour un projet spatial

📡 2. Framework de communication série / radio (Arduino / ESP32)
💡 Idée

Un framework logiciel qui simplifie la communication :

entre CANSAT et station sol

via UART, RF, LoRa ou Bluetooth

🛠️ Ce que tu développes

format de trames standard

gestion :

checksum

erreurs

reconnexion

API simple :

sendData(TEMP, 22.5);
sendData(ALTITUDE, 320);

⭐ Pourquoi c’est bien

✅ Très technique
✅ Montre que tu comprends les systèmes embarqués
⚠️ Un peu plus complexe à expliquer que le web

🛰️ 3. Framework de simulation de mission CANSAT
💡 Idée

Un framework qui simule une mission complète :

montée

séparation

descente

atterrissage

🛠️ Ce que tu développes

moteur de simulation simple

génération de données réalistes

événements (parachute, panne capteur)

simulateAltitude(t)
simulateTemperature(t)

⭐ Pourquoi c’est intéressant

✅ Super pour les tests
✅ Pas besoin de vrai matériel
✅ Très pédagogique

🔌 5. Framework de gestion de capteurs (embarqué)
💡 Idée

Un framework qui uniformise l’utilisation des capteurs :

température

pression

IMU

GPS

🛠️ API simple
Sensor temp("BMP280");
temp.read();
temp.calibrate();

⭐ Intérêt

✅ Très lié au CANSAT
✅ Montre une bonne architecture logicielle
⚠️ Demande un peu plus d’expérience embarquée
